# WebCHIRP for Android

The Google Play app `com.hf2j.webchirp`: a [Trusted Web
Activity](https://developer.chrome.com/docs/android/trusted-web-activity) that
opens https://webchirp.org full-screen in Chrome. Everything the user sees is
the website, so web changes reach the app on the next deploy; this project
only needs a new release when the app itself changes.

This directory is generated by [Bubblewrap](https://github.com/GoogleChromeLabs/bubblewrap)
1.27.0 from `twa-manifest.json`. Change the app by editing that file and
regenerating; never edit the generated files by hand, because the next
regeneration overwrites them. `tests/build/android-app.mjs` checks the
manifest against the site, and fails when the project was not regenerated
after an edit.

## Setup

```sh
npm install -g @bubblewrap/cli@1.27.0
cd android
bubblewrap doctor   # the first run offers to install JDK 17 and the Android SDK
```

## Regenerating after an edit

```sh
bubblewrap update --skipVersionUpgrade   # same version, e.g. a colour change
bubblewrap update                        # next versionCode, for a release
```

Bubblewrap's template still lists the retired `jcenter()` repository, so after
every regeneration replace both `jcenter()` lines in `build.gradle` with
`mavenCentral()`; `tests/build/android-app.mjs` fails until you do. Then commit
`twa-manifest.json`, `manifest-checksum.txt` and the regenerated files
together.

The launcher icons, splash screens and store icon are rendered from the site's
icons, so new artwork in `web/images/` means regenerating as well. Record each
icon's SHA-256 in `icon-sources.json` afterwards; the test that fails prints
the new value.

## Releasing

The upload key signs what you upload; Google re-signs every install with the
app signing key it holds (Play App Signing). Both stay out of the repository:
`.gitignore` excludes `*.keystore` and `*.jks`.

1. Once, create the upload key where `twa-manifest.json` expects it, and keep
   a backup somewhere safe -- a lost upload key has to be reset through Play
   support:

   ```sh
   keytool -genkeypair -v -keystore android.keystore -alias android \
     -keyalg RSA -keysize 2048 -validity 10000
   ```

2. Build the signed bundle (`app-release-bundle.aab`) and APK:

   ```sh
   bubblewrap update   # bumps appVersionCode
   bubblewrap build
   ```

3. Upload `app-release-bundle.aab` in Play Console. The first upload of a new
   app has to be made there by hand; the Play Developer API cannot create one.

4. After the first upload, copy the **app signing key** SHA-256 fingerprint
   from Play Console's App signing page into `sha256_cert_fingerprints` in
   `web/.well-known/assetlinks.json` (add the upload key's too, for test builds
   installed outside Play). Until that is deployed, the app opens with a URL
   bar.
