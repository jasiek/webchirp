# Findings

Durable, non-obvious facts about CHIRP, the browser runtime, and the project's infrastructure.
Grouped by topic; each entry starts with a **bold slug** (grep target) and carries its discovery date.
Record only the rule, the mechanism, and the pointer; history lives in git log. Prune entries when
the code or infrastructure they describe changes.

**When a test pins a finding, the test owns it.** An entry whose every claim is asserted in
`npm test` is reduced to a line in its section's *Pinned by tests* list; the mechanism lives in that
test's header. Prose is kept for what no test can assert: upstream defects we route around, external
API behaviour, browser and platform constraints, and rules about work not yet done.

Corpus counts (images, drivers, classes) are measurements against one CHIRP pin and drift on the
next bump; the method is the durable part. The pin is CHIRP `29592824` (2026-09-29): 558 radios from
195 driver modules, plus 3 drivers in the `drivers=quansheng-unofficial` catalog. Since this pin,
upstream `CloneModeRadio.match_model()` returns False by default, so a metadata-less image opens
only through a driver that opts in to legacy or external-format detection. Counts dated before
2026-10-03 were measured at an earlier pin.

## CHIRP / Pyodide runtime

- **the-rpc-surface-is-one-dispatcher** (2026-09-24, replaces *the-rpc-namespace-is-a-flattened-package* of 2026-09-08): JS reaches the Python runtime through exactly one callable, `rpc_dispatch` (`web/python/webchirp_bridge/rpc.py`), by method name, one JSON object of named parameters and an optional JS callback bound as the `callback` keyword, and gets back one JSON envelope rather than a raise (**runtime-errors-cross-as-an-envelope**); `RPC_METHODS` there maps each name to the owning module's function, and `RPC_METHODS` in `web/js/rpc-dispatch.mjs` repeats the names with their parameter names so a call is checked before it crosses. `web/python/runtime_bridge.py` is still *executed* into Pyodide's globals (it is the one runtime file coverage cannot map), but it now binds only `rpc_dispatch` -- nothing else in the package is reachable from JS, and no argument is ever passed through an interpreter global. `tests/channels/rpc-contract.mjs` pins the pairing from both ends with `inspect.signature`. Until 2026-09-24 the entry point copied every non-dunder name of every module into the globals and `web/js/runtime-rpc.js` evaluated strings like `json.dumps(parse_csv(_csv_input))` against `pyodide.globals.set("_csv_input", ...)` slots that were never cleared. The ~100 `harness.runPython()` snippets in `tests/` still rely on that flat namespace, which was judged not worth rewriting (the threshold was about 40), so the flattening moved to `tests/support/bridge_namespace.py`, run by `tests/support/radio-harness.mjs` after the production seed; production code cannot depend on it. Two rules from the old entry still hold. **Mutate through the global, patch through the module** (tests only now): the flattened values are shared, so a `RadioSession` a snippet resolves through the flattened `resolve_session()` is the object the modules use, but rebinding a global changes only the copy -- a module resolves its names in its own namespace, so a test that swaps a callable sets the attribute on the owning module (`pyodide.pyimport("webchirp_bridge.jsbridge").serial_log = ...`; `tests/channels/unreadable-channels.mjs`). **Every runtime file needs a URL the build rewrites**: `scripts/build-dist.mjs` hashes `.py` files and rewrites references in `.js`/`.html`/`.css` only, copying `.mjs` verbatim, so the URL table has to live in `web/js/runtime-rpc.js` (`RUNTIME_PYTHON_URLS`), not next to the file list in `web/js/python-sources.mjs`; `tests/build/build-dist.mjs` pins the pairing. (The third rule, importing `chirp.drivers` ahead of the CDN finder, died with the finder on 2026-09-24: upstream's `chirp/drivers/__init__.py` now ships in the archive -- see **chirp-ships-as-one-pin-named-archive**.)
- **async-pyproxy-calls-behave-like-runPythonAsync** (2026-09-24): calling an `async def` through a `PyProxy` returns an awaitable `PyProxy` of the coroutine, not a Promise, and `pyodide.ffi.run_sync` inside it works exactly as under `runPythonAsync` (`callPromising` is not needed). The coroutine proxy must be `destroy()`ed once settled or one leaks per call. `pyodide.isPyProxy` does not exist in 0.27, so `web/js/rpc-dispatch.mjs` checks for `destroy`. A JS function passed as an argument arrives as a callable `JsProxy`.
- **coverage.py-works-inside-pyodide** (2026-09-08): Pyodide ships `coverage` and its C tracer runs under WASM, so `npm run coverage` measures the real runtime. In `tests/support/python-coverage.mjs`: tracing must start between `loadPyodide()` and `seedPyodideRuntime()`, or module-level statements never register; use `include=["/webchirp_runtime/webchirp_bridge/*"]`, not `source=`, because `source=` treats the not-yet-written directory as a module name and silently reports zero. `web/python/runtime_bridge.py` is unmeasurable: it is executed as a string (`<exec>`), so coverage cannot map it. Each `node:test` file has its own Pyodide and writes a fragment, and `scripts/coverage.mjs` merges them.
- **no-jspi-browsers-lose-only-the-clone-path** (2026-09-24): only `pyodide.ffi.run_sync` (`_await_js` in `web/python/webchirp_bridge/jsbridge.py`) needs WebAssembly JSPI. CHIRP's blocking clone loops use it to wait on the serial bridge. Init, file editing and image export work without JSPI. `web/app.js` detects it (`WebAssembly.Suspending`/`.promising`) and calls `setCloneSupported` in `web/js/ui/serial-actions.js`, which refuses a connect and says why (`tests/channels/clone-button-gating.mjs`). Browsers without JSPI: Firefox before 152, Firefox ESR, Safari, Chrome before 137. Triage: `run_sync` fails with `RuntimeError: WebAssembly stack switching not supported in this JavaScript runtime`. `pyodide.ffi.can_run_sync()` answers the same question from Python. To reproduce on Firefox, set `javascript.options.wasm_js_promise_integration` to false. Firefox 152+ has JSPI and native `navigator.serial`.
- **static-driver-catalog** (2026-06-23, updated 2026-10-03): `web/radio-catalog.json` (558 radios from 195 modules) and `web/radio-catalog-quansheng-unofficial.json` are built ahead of time. `scripts/build-catalog.mjs` enumerates each unofficial module in its own Pyodide subprocess, so colliding registrations never coexist. The browser accepts a catalog only when its `chirpRevision` and `driverSet` both match `web/js/python-sources.mjs`. Upstream mode can fall back to live enumeration. Unofficial mode reports the catalog as unavailable rather than import releases that conflict. Driver module lists come from the archive manifest, and `driverModulesFromManifest()` refuses a manifest whose pin differs. `build:catalog` and `build:chirp` refuse to run on a drifted submodule. The picker needs no Pyodide, which boots lazily.
- **catalog-aliases-are-the-only-handle-on-rebadged-radios** (2026-09-06): a driver is filed under one vendor, so rebadges exist only in its `ALIASES` (e.g. `uv5r:BaofengUV5RGeneric` also covers Retevis RT5R, Rugged RH5R, Radioddity UV-5R EX and Ansoko A-5R, vendors found nowhere else in the catalog). Catalog entries carry `aliases` (`list_registered_radios()` in `web/python/webchirp_bridge/chirp_loader.py`). Search must include them and say which alias matched. Image-metadata matching uses the same list, which is why `rclass` cannot be a primary key (see **wrong-match-is-worse-than-no-match**).
- **gettext-builtins-come-from-wxui** (2026-07-27): drivers call `_()`/`ngettext()` as builtins, which upstream installs only in `chirpmain()` (`chirp/chirp/wxui/__init__.py`), a frontend we never load. `_install_gettext_builtins()` in `web/python/webchirp_bridge/__init__.py` installs passthroughs before importing `chirp`. It checks `callable()` rather than `hasattr`, because a REPL binds `builtins._` to the last result. Treat this as setup for the whole runtime: every submodule bump adds call sites.
- **f4hwn-release-archive-is-bundled-lazily** (2026-09-22): v4.3.2, v5.9.0 and v6.0.0 (`QUANSHENG_UNOFFICIAL_DRIVERS` in `web/js/python-sources.mjs`, files in `web/python/extra_drivers/quansheng/`) load only with `?drivers=quansheng-unofficial`. v4.3.0 to v4.3.2 shipped identical driver bytes. Every v5 class has the same vendor/model/class identity, so each release runs in its own runtime. Switching releases discards the session's image. The drivers import desktop-only `wx`; the cancel-by-default shim keeps advanced and calibration writes from being approved silently. They declare neither `_memsize` nor `match_model`, so WebCHIRP cannot build an offline image or detect a metadata-less image for them. Nobody has tested real-radio clones with them.
- **f4hwn-image-selection-is-required** (2026-09-23): importing an unofficial image requires the user to pick a firmware release first, then runs native detection with only that release imported. The shared v5 metadata cannot identify the release, so a metadata match does not prove the user picked the right one.
- **upstream-tests-skip-power** (2026-07-29): CHIRP has no byte-level image round-trip test. `test_brute_force.py::test_get_set_all` does get → set → get, but `assertEqualMem` (`chirp/tests/base.py`) skips `power` (`# FIXME`), so power round-trip bugs go unnoticed upstream. For example, `ftm7250d.FTM7250Radio` swaps Hi and Low. `chirp/tests/driver_xfails.yaml` lists only brute-force xfails, so every image in `tests/images/` should detect and load cleanly.
- **idrp-never-registers** (2026-07-30): `idrp.IDRPx000V` has no `@directory.register` upstream, so it is missing from the catalog even in desktop CHIRP. This is not a pyserial-shim bug.
- **blank-instances-misreport-state** (2026-03-14, widened 2026-09-13): `radio_cls(None)` is not a smaller version of a parsed instance; it behaves differently. On a blank instance, `get_settings()` can throw, so fall back to `radio_cls("")` for metadata. `get_features()` can differ too: `retevis_rt98.Rt98Radio` lists one power level blank and three once an image is parsed. `valid_bands` can be `(0, 0)` (`icw32.ICW32ARadio` reads limits from the codeplug), and `_describe_features()` (`web/python/webchirp_bridge/chirp_loader.py`) drops empty ranges. Rules: anything derived from `get_features()` goes through `RadioSession.describing_instance()`/`features()` (`web/python/webchirp_bridge/session.py`), which prefer the backing image, never through `_blank_radio_instance()`. Every path that stores an image re-fetches rows first and schema second, because `applyRadioMetadata` (`web/js/ui/radio-catalog.js`) clears any `Power` value its schema does not list (issue #86).
- **radio-features-are-unordered-at-the-source** (2026-09-13): some drivers build capability lists with `list(set(...))` (`ft817` `valid_modes`, `id31` `valid_tmodes`), so their order changes from one process to the next. `_describe_features()` sorts every list at the boundary (`tests/build/radio-features.mjs`). If a rebuild diffs with no code change, suspect this before suspecting a CHIRP change.
- **skip-immutable-on-apply** (2026-03-14): replaying serialized values onto a fresh settings tree hits immutable fields, which raise `This value is not mutable` (`chirp/chirp/settings.py`). `_setting_value_is_mutable()` skips them.
- **dead-settings-must-be-pruned-before-write** (2026-09-07): a setting CHIRP could not load stays in the `get_settings()` tree with `_current = None`, because `RadioSettingGroup.__init__` swallows the error. Whether writing that tree back survives depends on the driver. `uv5r.set_settings()` writes every element and fails with `TypeError` (integer) or `ValueError` (list) on `None`. No corrupt codeplug is needed: `uv5r`'s `abr`/`squelch` ranges are narrower than their `u8` fields. Desktop CHIRP strips such settings (`_remove_dead_settings`, `chirp/chirp/wxui/settingsedit.py`). `_prune_dead_settings()` does the same on a copy, so the UI still shows them (issue #75).
- **upstream-get-max-defect** (2026-03-14): `RadioSettingValueFloat.get_max()` has no `return` (`chirp/chirp/settings.py`), so serialize float bounds from `_max`.
- **parse-freq-negative-defect** (2026-07-30): upstream `chirp_common.parse_freq()` always adds the fractional part: `parse_freq("-0.600000")` returns +600000 and `"-5.600000"` returns −4400000. CSV rows from `to_csv` are unaffected, but a typed or imported negative offset is corrupted. `to_MHz(float())` gets the sign right but truncates. Reject negative offsets before parsing.
- **a-python-loop-paints-only-when-it-yields** (2026-07-30, rewritten 2026-09-24): a Python loop inside one dispatched call updates the UI only if each iteration yields to the JS event loop. Both bulk sweeps (`import_all_driver_modules()` and the catalog fallback `list_registered_radios()`) are `async` and share `_import_driver_modules()`, which runs `await asyncio.sleep(0)` (one `setTimeout` hop) after each module (`tests/channels/chirp-archive-boot.mjs`). If a loop must show progress, pass a callback and yield explicitly rather than split it into one RPC per item. `rpc_dispatch` awaits coroutines, so callers do not change when a method becomes async.
- **the-first-yield-moves-python-off-the-jspi-stack** (2026-09-26): in Chrome, the per-import yield also makes the sweep about 7× faster (~1.0 s vs ~6.9 s for 194 modules). A single yield before the loop is enough, and the yields themselves cost nothing. Node shows no difference, so no test can catch a regression. Hypothesis: a dispatched call runs on a JSPI suspendable stack, where every Wasm-to-JS call (each filesystem syscall) pays a stack switch, and the first `await` moves the rest onto the ordinary stack. Rule: a long synchronous stretch dispatched from JS yields once before it starts.
- **all-driver-import-mechanics** (2026-07-30): the sweep is cached per session as a promise that resets on failure. `import_all_driver_modules()` tolerates failures per module and logs each one as `DRIVERS SKIP <module>: <error>` (`web/js/runtime-rpc.js`). At this pin every module imports, but keep the reporting, because grepping for `import serial` cannot judge importability (`hf90`/`tmv71_ll` import it inside functions). `scripts/build-catalog.mjs` calls the same function, so the catalog warnings and the runtime skip lines cannot disagree.
- **chirp-ships-as-one-pin-named-archive** (2026-09-24): `scripts/build-chirp-bundle.mjs` zips the pinned `chirp/chirp` package (about 1.6 MB), and `pyodide.unpackArchive(..., { extractDir: "/webchirp_runtime" })` mounts it. The excluded directories were chosen by grep, and `tests/build/chirp-bundle.mjs` reruns it. Non-obvious points: (1) `fflate` `zipSync` writes every entry with a fixed 1980-01-01 mtime, so builds are byte-identical. That is why the archive is named by pin rather than by content hash, and why `scripts/retain-deployed-assets.mjs` must keep the `chirp-<40 hex>.(zip|json)` names, or the previous pin 404s while Pages caches are stale. (2) Pass `unpackArchive` a fresh `Uint8Array`, because a Node `Buffer` may alias the shared pool. (3) Upstream's `chirp/drivers/__init__.py` ships, so `chirp.drivers` is a regular package. (4) Unofficial Quansheng drivers are written over the mounted tree only when that driver set is selected (`web/js/selected-driver-runtime.mjs`). (5) `tests/support/chirp-bundle-source.mjs` builds the same archive in-process.
- **transport-disconnect-events-name-different-things** (2026-08-24): native Web Serial fires `disconnect` at the `SerialPort` itself, so `event.target` matches by identity. WebUSB fires at `navigator.usb` with `event.device`, a `USBDevice`. Our chip drivers keep it as `port.device`, but the CDC polyfill keeps it private, leaving vid/pid from `getInfo()` as a fallback that cannot tell identical adapters apart. A radio switched off behind a cable that stays connected fires no event; it shows up only as a clone timeout.
- **shim-owes-pyserial-return-values-not-just-methods** (2026-09-05): drivers read `WebSerialPipe` return values, not just its method names. `write()` returning `None` instead of a byte count broke `puxing_px888k.pipewrite` (`if n is None: raise`, issue #79), while `tk11`'s `== 0` check silently passed. To audit, grep drivers for code that *uses* the return values, not for method names.
- **the-pipe-is-reconfigured-mid-clone** (2026-09-05): drivers reconfigure `self.pipe` mid-clone, so `WebSerialPipe` (`web/python/webchirp_bridge/serial_pipe.py`) must match pyserial's exact signatures. `setRTS()`/`setDTR()` take an optional level: `thd72` calls `setRTS()` bare (issue #77). Line changes push through `serial_set_signals`, except during construction (`_new_serial_pipe()`), where `_prepare_clone_session()` asserts them together with the settle delay. `baudrate` and framing push through `serial_reconfigure`, which reopens the port (see **baud-rate-is-latched-at-open**). A mid-clone reopen (`_reopenPort()` in `web/js/serial.js`) differs from the reopen at clone start in three ways. It **keeps buffered bytes**, as pyserial's `TCSANOW` does (`thd72` reads right after switching rate). It snapshots the buffer only after the reader loop has stopped and restores it before the next loop starts. It **re-asserts DTR/RTS**, because closing the port drops them. It **reopens only on a real change**, because drivers re-assign the rate they already have. Failure handling differs too: `applyBaudRate()` tears the session down, while `reconfigure()` restores the previous settings and keeps the session. Both propagate the error.
- **framing-is-set-after-open-but-never-mid-clone** (2026-09-05, CHIRP `80d93fe5`): every `parity`/`stopbits`/`bytesize` assignment comes before the operation's first byte but after the port opened (e.g. `tg_uv2p`/`tk8180` two stop bits; `tk280`/`ft2800`/`tk760g`/`tk8102`/`hg_uv98` even parity; `ft450d` all four). These go through the same reopen as the rate, on transports that support them (not the WebUSB chip drivers, see **webusb-chip-ports-are-8n1-only**). Deliberately ignored: `xonxoff`, which no driver assigns; `rtscts`, which is only ever `False`; and `tk3140`'s `pipe.databits` typo, which is dead on real pyserial too. Expect probe loops that reopen up to six times (`thd72`/`thd74`/`tmv71`, `ts480`/`ts590`, `tmd710`). `icf.start_hispeed_clone` switches to 38400 mid-clone for 11 Icom modules with `_can_hispeed = True`. `tmd710` formats `pipe.baudrate` with `%i`, so the pipe is seeded from `BAUD_RATE`.
- **pyserial-peeks-are-not-free-here** (2026-09-05): `in_waiting` returned a hardcoded 0, and the legacy `inWaiting()` was missing. The missing alias crashed every `AnyTone778UVBase` clone. A constant 0 fails silently: a driver that reads only when bytes are waiting gets an empty response. Drivers poll the peek in tight loops (pyserial answers from a kernel buffer), but here each peek is a JSPI round trip. So `BrowserSerialBridge.inWaiting(waitMs)` waits on the read event while the buffer is empty, for up to `IN_WAITING_WAIT_MS` (40 ms), which must stay well under the drivers' 0.5 s deadlines. These radios also needed **detection-is-part-of-the-clone-not-a-lookup** (issue #81).
- **detection-is-part-of-the-clone-not-a-lookup** (2026-09-05): for `ga510`, `tdh8`, `anytone778uv` and `tdm11`, `detect_from_serial()` is the first step of the clone protocol: it puts the radio into programming mode, and `do_download()` assumes it has run. `leixen`, `h777` and `uvk5` use it to choose a subclass. Rules (`_create_radio_for_serial()`, `web/python/webchirp_bridge/clone.py`): detect and clone on **one pipe object**. Treat `NotImplementedError` as "use the selected class", but let `RadioError` propagate. Upload does not re-detect (`chirp/wxui/clone.py`). The detected class is state, `RadioSession.detected_cls`, and every re-parse reads `image_cls`. `RadioSession.record_radio()` serializes the image before it records the class, so a failed `save_mmap()` cannot tag the previous bytes with the new class. `load_image_base64()` likewise keeps a `DynamicRadioAlias` as `detected_cls`.
- **runtime-errors-cross-as-an-envelope** (2026-09-29, replaces *errors-lose-their-identity-crossing-pyodide* of 2026-09-06): until this date a Python exception crossed the boundary as *text*: Pyodide raised a `PythonError` whose message was the whole traceback, `wrapRuntimeMethod` (`web/js/runtime-rpc.js`) rethrew `new Error(thatText)`, and every classifier in the UI re-derived the class with a regex over it — the precondition notice, the `ImageDetectionError` retry, the Sentry ignore rules, `error_type`, the port-chooser cancellation (which only worked because the sentence "No port selected" survived onto the traceback's last line) and every `error_kind` bucket — so wording was contract. Now `rpc_dispatch` (`web/python/webchirp_bridge/rpc.py`) never lets an `Exception` out: it answers `{"ok": true, "result": ...}` or `{"ok": false, "error": {type, bases, module, message, traceback, causes, js}}` from `rpc_error_envelope`, and `unwrapRpcEnvelope` (`web/js/rpc-dispatch.mjs`) throws a `RuntimeCallError` (`web/js/runtime-errors.mjs`) whose `name` is the Python class and whose `message` is `str(exc)` alone; classifiers call `isPythonError(error, "X")`, which matches the class or any base. Five things are not obvious from the code. **A `JsException` keeps the JS error's `name` and `message` as attributes** (Pyodide 0.27; `str()` is `"Name: message"`), and the envelope walks `__cause__`/`__context__` to the first one, so a driver that re-raises a serial failure as a `RadioError` still reports the JS name in `js`. The port chooser arrives there as `PortSelectionCancelledError`, not `NotFoundError`: the bridge (`web/js/serial.js`) translates the chooser's `NotFoundError` before Python ever awaits it. **Bases are bare class names**, so a rule meant for one CHIRP class must be exact on `type` *and* `module` — `RuntimeUnsupportedError` and `ImageDetectionError` list `RadioError` among their bases, and a base match on the ignored CHIRP classes' parent would swallow them. **V8 formats `stack` when the error is constructed**, before the subclass sets `name`, so a `RuntimeCallError`'s stack still begins `Error: ...`; `errorDetails` (`web/js/ui/format.js`) therefore builds a runtime failure's detail from `runtimeErrorDetail` — one `Type: message` line, the Python traceback, then the JS frames — rather than from `stack` -- taking from `stack` only its frame lines, in V8's `at` syntax or the `fn@url:line:col` syntax Firefox and Safari write, whose stacks carry no headline at all -- which also gives `errorSummary`, the serial log and the Report Bug prefill a real first line instead of "Traceback (most recent call last):". **Text matching remains in three places, each for a reason**: `error_kind` buckets for causes that have no type (a CHIRP driver raises a bare `RadioError("Radio did not respond")`), matched now against the message, the messages of the exceptions it was chained from (`causes`: a driver such as `iradio_uv_5118plus` re-raises "Block failed checksum!" as "Failed to read block", and only the inner one says checksum) and the JS cause, rather than the traceback, whose file and function names used to match patterns meant for the sentence; `errorTypeName`'s read of a traceback's last line, kept only for a `PythonError` raised while seeding the runtime, before the dispatcher exists; and Sentry's `ResizeObserver loop` pattern, a native browser error. **`harness.runPython()` snippets bypass the dispatcher** and still reject with Pyodide's `PythonError` text; a test that wants the typed error calls `harness.rpc()`. The rule the old entry stated about the app having no status line still holds: `setStatus()` writes into the Debug Output panel (`web/js/ui/debug-log.js`), so a failure that is not logged there has nowhere else to surface.
- **undecodable-memories-couple-download-to-erase** (2026-09-06): in `web/python/webchirp_bridge/radio_memories.py`, download skips any memory that `get_memory` cannot decode, and upload erases every valid number that is missing from the rows. A decode failure would therefore become an erase. Checking readability before erasing is not enough, because upload rebuilds a fresh instance from the image and a one-off decode failure may not repeat. So the numbers are stored at extraction as `RadioSession.unreadable_channels`, overwritten on every read, and removed from the erase candidates. A row the user supplies for one of those numbers still writes. The protection lasts only for that session (`tests/channels/radio-session.mjs`). Upstream renders error rows instead; we return `unreadableChannels`, because a placeholder row could be mistaken for a writable one.
- **a-radio-session-is-the-unit-of-runtime-state** (2026-09-26): one `RadioSession` (`web/python/webchirp_bridge/session.py`) per selection. Points the code does not make obvious: **the session belongs to the selection, not the driver**. Selecting another radio closes it, so an image downloaded for A is gone after moving to B and back. **An image load opens a session**: the image decides the driver, so `load_image_base64()` opens one, and the browser adopts the returned `sessionId` (`selectRadioByDetectedImage()` in `web/js/ui/radio-catalog.js`). **A session lives in one interpreter**: `web/js/runtime-rpc.js` maps session id to the Pyodide that opened it (isolated Quansheng runtimes), and ids carry a random suffix. **An abandoned selection never reaches the runtime**: `idOf()` (`web/js/ui/radio-session.js`) throws for a handle closed before its id was used. Tests get sessions via `harness.session()`/`open_radio_session()`, or `withRadioSessions()` (`tests/support/fake-runtime-api.mjs`) for fake-DOM tests.

*Pinned by tests:*
- **offline-export-is-not-a-radio-image** (2026-09-07): `export_image_base64()` can build an `.img` on a zeroed `_memsize` base. Each image carries an `ImageOrigin` (`radio`/`file`/`synthetic`), and only the first two count as `RadioSession.backing_image` for upload, settings and image-backed instances — `tests/channels/radio-session.mjs`.
- **exception-text-is-an-unbounded-grouping-key** (2026-09-06): drivers put the channel number in their messages, so grouping failures by message text does not limit output. `MAX_LOGGED_FAILURE_GROUPS` caps the groups, and `_log_grouped_channel_failures` sorts them by channel count — `tests/channels/unreadable-channels.mjs`.
- F4HWN sources stay byte-identical to their releases, load lazily in separate runtimes with searchable release labels, and v6 round-trips channels, settings and an image — `tests/channels/f4hwn-releases.mjs`, `tests/build/build-dist.mjs`.
- The JS and Python RPC tables agree. Session ids are resolved only in `RPC_METHODS` entry points. A failed image load closes its session, and a handle whose open failed is not reused — `tests/channels/rpc-contract.mjs`, `tests/channels/radio-session.mjs`.
- All Pyodide RPCs go through the FIFO queue (`web/js/call-queue.mjs`). Each selection opens a session and closes the previous one. A load is applied only while its handle is current, and an abandoned selection calls nothing — `tests/channels/call-queue.mjs`, `tests/channels/ui-radio-loading.mjs`, `tests/channels/radio-session.mjs`.
- The runtime boots from the archive alone: no meta-path finder, upstream `chirp/drivers/__init__.py`, and both sweeps yield between imports. ## Channel grid / CSV

- **csv-radio-is-not-a-round-trip-surface** (2026-07-30): `generic_csv.CSVRadio` is CHIRP's import/export vehicle, not a lossless staging format. A header-only CSV raises `InvalidDataError("No channels found")`, so the startup column schema comes from `Memory.CSV_FORMAT` directly. `CSVRadio(None)` seeds a non-empty channel 0 (146.010000/50W) that only the filename `load()` path blanks; upstream erases it by hand (`chirp/chirp/wxui/memedit.py`), so build any new one with `_blank_csv_radio()`. `_load()` drops zero-frequency rows, yet drivers report and CHIRP exports non-empty memories with no frequency (`Icom_IC-W32A`, `Jetstream_JT220M`), so `_memories_from_rows()` parses each row with `CSVRadio._parse_csv_data_line()` instead of `load_from()`.
- **csv-export-is-import-logic** (2026-07-30): CHIRP's CSV export pushes each memory through `import_logic.import_mem()` into a `CSVRadio` (`_export_to_file`, `chirp/chirp/wxui/memedit.py`), not `Memory.to_csv()`. So power is always watts (`AutoNamedPowerLevel(dBm_to_watts(...))`; `int()` on a `PowerLevel` truncates the dBm, writing 50W as `39W`), tone/DTCS columns the source does not track are filled (rtone→ctone, dtcs→rx_dtcs), and an incompatible memory is logged and written unconverted, not dropped. `normalize_rows()` mirrors this.
- **dvmemory-to-csv-layout** (2026-07-30): `DVMemory.to_csv()` still emits the old 18-field layout against `Memory.CSV_FORMAT`'s 21, shifting every column from `RxDtcsCode` on. `_row_values_for_csv()` clones DV memories into a plain `Memory`, as CHIRP does; call signs are dropped either way.
- **power-labels-beat-watts-in-rows** (2026-07-30, re-measured 2026-09-14): rows carry power as the driver's label, not watts. No driver advertises duplicate labels, but 8 classes collapse onto the same watt string after 1-dp rounding (e.g. `retevis_rt21.RT619Radio`, `radtel_t18.RB619Radio`), and CHIRP itself shows labels except for `has_variable_power` radios. Cost: some modules keep an unadvertised band-keyed level list (`vx6`/`vx7.POWER_LEVELS_220`, `ft90`), so a label under-determines watts outside the primary band and our CSV writes the advertised value; radio writes are unaffected because those drivers re-resolve power from frequency. For the same reason the label→watt hover legend (`_power_level_watts()`) is column-level, not per channel.
- **set-memory-is-not-a-tone-backstop** (2026-07-29): many drivers encode rtone/ctone/dtcs raw without checking `TONES`/`DTCS_CODES`, and nothing replaced the check `Memory.really_from_csv()` used to do. The UI's enum dropdowns constrain the browser path; external CSV through `npm run radio:write` can plant a nonstandard tone silently.
- **rows-not-bytes-for-round-trip** (2026-07-29): load→export rarely preserves bytes (padding and unused regions move) even when every row is identical. Compare rows field by field (`tests/channels/channel-round-trip.mjs`); byte-identity is a bonus.
- **location-is-a-memory-slot-not-a-row-index** (2026-09-05): `Location` is the memory slot and must never be derived from row position. Radio codeplugs are sparse (`Baofeng_UV-5R.img` fills 37 of 128 slots) and slot numbers matter to scan lists and the dial; bounds start at 1 as often as 0, even within one module (`uv5r.BaofengUV5R` is `(0, 127)`, `BaofengUV6Radio` `(1, 128)`). Every row operation calls `reconcileLocations()` (`web/js/ui/channel-table.js`): `assignFreeLocations()` keeps valid unclaimed Locations and gives the rest the lowest free slot within the Location column's `min`/`max` (from `memory_bounds`), then `sortRowsByLocation()` enforces **row order is memory order**. Rows reselect by identity (`selectRowsByIdentity`), not index. Move Up/Down rotates channels through occupied slots. Loads call `sortRowsByLocation()` alone so bad Locations from a file reach the upload preflight unaltered, and paste targets consecutive memories, not consecutive rows.
- **rows-are-a-lossy-projection-of-memory** (2026-09-07): `Memory.extra` holds per-channel driver settings with no grid column (BCL, PTT-ID, scramble...). About half the driver modules populate it, and many replay it in `set_memory()` after wiping the record with `set_raw()`, so a `Memory` rebuilt from a row alone resets those settings. Extras belong to the channel, not the slot (Move Up/Down, delete-and-replace), so they ride on the row under the non-header key `__extra` (`web/js/row-extra.js`), which no serializer emits; rows not from a driver have none and take driver defaults. They are applied **after** the write by re-reading the memory, so the driver's own setting objects are used and an empty destination slot works. Because `_prepare_row_change()` skips rows equal to their memory, the skip branch in `_apply_rows_to_radio_instance` replays the sidecar and writes only on a real difference — otherwise an extras-only edit would be lost. `Baofeng_UV-17.img` (channel 1 `scode` 2) is the fixture that exposes the bug.
- **extras-have-no-schema-until-a-memory-is-read** (2026-09-09): the sidecar is bare values, so the editor fetches the schema per open (`get_channel_extra`, `web/python/webchirp_bridge/channel_extra.py`) and overlays the row's values. A schema exists only for driver-decoded memories, so the Extra column shows only when some loaded row carries extras. The column is synthetic — appended after Comment and kept out of `state.currentHeaders`, which every serializer projects through. Per-row "has extras" markers are useless (a clone marks every row). Values use the settings panel's `_serialize_setting_value`, so controls match.
- **extras-bypass-the-preflight-unless-asked** (2026-09-09): `_prepare_row_change()` returns `skip` before `validate_memory` for an extras-only edit, yet some drivers validate extras (`hf90`, `ft450d`, `ar8200`); and a value the driver refuses at write time is silently kept at the destination's value, since aborting mid-clone would half-program the radio. `_row_extra_findings` (`web/python/webchirp_bridge/row_validation.py`) reports both against the `Extra` column in the preflight. For tests: `RadioSettingValueBoolean` accepts anything; only List/Integer values raise.
- **grid-cost-is-option-lists** (2026-07-27): grid DOM size is dominated by `<option>`s (~380 elements per UV-5R row), so `web/js/ui/channel-table.js` virtualizes: only rows overlapping `#mem-table-scroll` plus overscan exist, recycled by rebinding, with delegated events. Find-in-page and Tab reach only rendered rows, and DOM readers must select `tr[data-row-idx]`, not index `tbody.children`.
- **grid-width-comes-from-its-editors** (2026-09-08): `#mem-table` is `width: max-content`, so column width is the editor's width. Selects size to their widest option (no `min-width`; native arrow replaced by an `appearance: none` chevron). Inputs use `field-sizing: content` (`web/styles.css`), which fails silently unless combined right: a percentage `width` disables it (needs `width: auto`), `min-width: 100%` fills the cell without feeding back, `max-width` is only a backstop for free text. Under virtualization a column tracks only the rendered rows. Do not put `min-width: 100%` on the table (slack is spread into every column) or `width: 100%` on one column (squeezes the others instead of scrolling).
- **sticky-header-loses-its-collapsed-border** (2026-09-09): header `th` cells are `position: sticky` within `.mem-table-scroll`. In a `border-collapse: collapse` table a sticky cell's borders stay with the table and scroll away (a stuck header's border paints nothing), so the edge is an inset `box-shadow` — not a border, which would change the header height `visibleRowRange()` subtracts. Sticky keeps the header in flow, so virtualization needs no change.
- **markup-defaults-are-the-boot-state** (2026-08-02): the grid is first rendered only after the runtime boots and `init()` (`web/js/ui.js`) has loaded catalog, metadata and settings, so `index.html`'s markup is what users see during boot and after an `init()` failure. Markup defaults for JS-toggled elements must be the pre-runtime state.
- **file-drop-wiring** (2026-07-27): the drop overlay must stay `pointer-events: none`, or it becomes the drag target and cancels the drag. Files route by extension (`web/js/ui/codeplug-io.js`), because `.img` and CSV MIME types vary by platform.
- **optional-fields-need-novalidate** (2026-09-14): a form with opt-in fields cannot carry native constraints: an abandoned out-of-range `min`/`max` input makes the form invalid, `submit` never fires, and Apply silently does nothing. `web/js/ui/channel-bulk-edit.js` is `novalidate` and validates ticked fields itself (`readSettingControl`, `normalizeCellValue`). The test DOM has no constraint validation, so `tests/channels/ui-channel-bulk-edit.mjs` can only assert the attribute. Any future per-field opt-in dialog inherits this trap.

## Repeater directories

- **rsgb-etcc-api-shape** (2026-07-31): `https://api-beta.rsgb.online` (self-documenting HTML at `/`) sends `Access-Control-Allow-Origin: *`, so it needs no proxy, but `OPTIONS` returns 405: requests must stay simple (plain GET, no custom headers such as `Accept`). Endpoints are `/<name>/<arg>` with the arg mandatory (without it you get the HTML index). `/band/`, `/locator/`, `/callsign/`, `/keeper/`, `/all/<anything>` return `{"data":[…]}`; `/aprs/<call>` returns `{"callsign","passcode"}` unwrapped. It never returns an HTTP error: unknown inputs are `200` with `{"data":null}`, so null-check the payload.
- **rsgb-locator-lookup-is-not-a-prefix-search** (2026-07-31): `/locator/` is exact-match except at exactly 4 characters, where it prefix-matches. A 6-character query misses records stored at other precisions (~26% carry only 4 characters), and 2- or 5-character queries return null. Query 4-character squares and rank distance client-side, or fetch `/all/systems` (555 KB raw, 73 KB gzipped).
- **rsgb-record-semantics** (2026-07-31): `tx`/`rx` are integer Hz from the repeater's side: channel frequency is `tx`, offset `rx - tx`. `tx == rx` means simplex (gateways, hotspots, packet) and is more reliable than the undocumented `type` code. `ctcss` `0` means no tone; `txbw` is kHz; `dbwErp` is dBW. `modeCodes` can be null; DMR appends colour code `M:1`…`M:15`. `status` may be the empty string. `id` is the only unique key: one callsign can hold several ports.
- **rsgb-has-no-lat-lon** (2026-07-31): no coordinates; position comes from `locator` or `extraDetails.ngr` (OS grid ref, OSGB36, so comparing it to a WGS84 fix needs a datum shift). A 6-character box over the UK is ~4.6 km N-S by 4.5–6 km E-W (not the equatorial 9.3 km); a 4-character centre can be ~70 km out, so web/js/rsgb.js flags those entries `approximate` and the preview map marks their pins as such (web/js/ui/static-map-view.js).
- **coep-blocks-plain-cross-origin-images** (2026-08-17): only `scripts/dev-server.mjs` sends `Cross-Origin-Embedder-Policy: require-corp` (GitHub Pages cannot). Under it a plain cross-origin `<img>` is silently blocked (`ERR_BLOCKED_BY_RESPONSE.NotSameOriginAfterDefaultedToSameOriginByCoep`). OSM tiles send ACAO `*`, so `img.crossOrigin = "anonymous"` (web/js/ui/static-map-view.js) satisfies COEP; it is set unconditionally. Any new cross-origin asset needs CORS mode plus ACAO, or a `Cross-Origin-Resource-Policy: cross-origin` upstream.
- **przemienniki-rxf-carries-wgs84-coordinates** (2026-08-17): each RXF `<repeater>` (przemienniki.net and RepeaterBook endpoints share the format) may carry decimal WGS84 `<location><latitude>/<longitude>`, but not always (105 of 116 in a sample); treat them as optional per row.
- **irts-api-mostly-matches-the-shared-rxf-contract** (2026-08-27): `https://api.codeplug.org/irts` returns the same RXF XML and accepts the same `country`, `band`, `mode`, `onlyworking`, `latitude`, `longitude`, `range` parameters; `/irts/meta` returns the shared filter dictionary. It covers `ie` and `gb` (incl. Northern Ireland), so take its options from `/meta`, not a hard-coded list. It labels `<qrg>` from the radio's side (`<perspective>radio</perspective>`) while przemienniki.net uses `repeater`; the perspective element is authoritative and a missing or unknown value must fail the query. IRTS is first-party, so it stays offered when the proxy base is blank.
- **only-the-range-bounds-an-rxf-query** (2026-09-19): RXF directories answer an unfiltered query in full: RepeaterBook with no filter returned 18.4 MB, `country=us` 10.1 MB, while lat/lon/`range=30` returned 68 KB, and adding `country` to a position changed nothing. `requires`/`unmetRequirement` (web/js/ui/repeater-sources.js) demand country or position for the three RXF sources; country-only US is knowingly allowed so small countries can import whole. RSGB has no country parameter and requires a position.
- **rxf-dictionaries-advertise-unimportable-modes** (2026-09-14): the RXF `/meta` dictionaries list digital modes under inconsistent names (`c4fm`/`fusion`, `apco25`/`p25`, `mototrbo`/`dmr`, …). Only `fm` and `dstar` make useful rows, so `markUnsupportedModes` (web/js/ui/repeater-sources.js) disables everything else generically instead of naming each source's modes.
- **rxf-perspective-governs-ctcss-not-just-qrg** (2026-09-06): `<perspective>` applies to the whole record, so `<ctcss type="rx">` follows the same side as `<qrg type="rx">`. przemienniki.net is `repeater` (a lone `rx` tone is the access tone the radio transmits); RepeaterBook and IRTS are `radio`. The mistake is invisible whenever both tones are equal (issue #103).
- **rxf-ctcss-is-not-always-a-ctcss-frequency** (2026-09-06): RepeaterBook puts `CSQ`, `Restricted` and DTCS codes (`D023`) in `<ctcss>`. `parseCtcssFreq` (web/js/datasources.js) accepts only a positive number, otherwise a carrier-squelch repeater is dropped as needing an untransmittable tone. Importing DTCS codes (`DtcsCode`/`RxDtcsCode`/`DtcsPolarity`) is not done.
- **a-tone-without-its-mode-is-inert** (2026-09-06): `chirp_common.split_tone_encode` reads `rToneFreq` only under `Tone`, `cToneFreq` only under `TSQL`, both under `Cross`, so an importer setting a tone must set the mode that encodes it. `applyTonePair` (web/js/datasources.js) mirrors `split_tone_decode`. Gate `Cross` on the Tone column's options, never on `CrossMode`: `valid_cross_modes` defaults to the full list even when `has_cross` is false.
- **setrowvalue-drops-writes-silently** (2026-09-05): `setRowValue` validates rather than assigns: `normalizeValue` (web/js/ui/channel-values.js) keeps the previous value for an out-of-band `freq`, out-of-range `int`, read-only column, or unknown `enum` (falling back to `previous ?? options[0]`, which looks programmed). `Offset` skips the band check, so a rejected frequency leaves a plausible offset and a blank Frequency, which upload reads as "erase this memory" (issue #101). Callers must check the returned acceptance flag (`normalizeCellValue` returns `{ value, accepted }`) before committing a mode that encodes the value; the row builders return `{ rows, skipped }` with reasons `frequency`/`mode`/`tone`. A receive-only tone that fails costs only the squelch, so that row is kept.
- **fetch-has-no-application-timeout** (2026-09-07): a stalled `fetch()` waits for the browser's own timeout (~300 s in Chrome). Directory requests run under `withRequestTimeout` (web/js/request-timeout.js, 10 s). The deadline must wrap the body read, since `fetch()` resolves on headers. Use an `AbortSignal` (a header would trigger RSGB's failing preflight; `Promise.race` leaves the connection streaming), and our own controller so the error can say "timed out", which `classifyErrorKind` (web/js/ui/analytics.js) matches on.
- **chirp-has-no-no-radio-state** (2026-09-09): desktop CHIRP with nothing loaded is `generic_csv.CSVRadio`, whose features are deliberately permissive (all modes, tone modes, cross modes, 50 tones, 1 Hz–10 GHz, 999-char names). `get_default_schema()` (web/python/webchirp_bridge/column_metadata.py) reports it and `loadEmptySchema` (web/js/ui/codeplug-io.js) installs it, so the no-radio grid uses the same validation path. Only CSVRadio sets `has_infinite_number` (Location has no max); it leaves `has_cross` False with a full `valid_cross_modes`, so CrossMode is read-only there while imports may still write Cross.
- **options-zero-is-not-a-default** (2026-09-09): `options[0]` is a bad default (WFM for mode, 67.0 for tones). `get_radio_column_metadata` publishes per-column defaults from `chirp_common.Memory()` (FM, 88.5, 023, NN, Tone->Tone), omitted when the driver lacks that value. Power defaults to blank, deliberately not an option: power labels are per-driver vocabulary, and a level seeded under one schema fails `validate_rows_for_upload` under another. Blank is `Memory().power is None`.
- **fr-tracks-floor-at-min-content** (2026-09-09): a bare `1fr` track is `minmax(auto, 1fr)`, floored at the item's min-content width, so a wide item widens the column instead of clipping, and percentage widths on it have nothing definite to resolve against. Use `minmax(0, 1fr)` plus a definite item width (`.modal-grid`, web/styles.css). The fake DOM in `npm test` has no layout, so only a real browser catches this.
- **hidden-is-only-a-user-agent-rule** (2026-09-09): `hidden` is a UA `display: none`, and any author `display` overrides it. An element given `display: flex` etc. needs an explicit `[hidden] { display: none; }` rule (`.modal-map-preview-empty[hidden]`, `.channel-toolbar button[hidden]` in web/styles.css). Invisible to `npm test` (no cascade).
- **centred-overlays-hide-their-own-top** (2026-09-09): `align-items: center` on a full-screen flex overlay pushes a taller child's top past the scroll range, unreachable even with `overflow: auto`. Use `align-items: flex-start` plus `margin: auto` on `.modal-card` (web/styles.css), shared by every modal. Invisible to `npm test`.
- **rsgb-contract-tests-are-opt-in** (2026-07-31): the rsgb- entries above are pinned only by `tests/manual/rsgb-live.mjs` (`npm run test:api`, needs the network); unit tests use fixtures and stay green if upstream changes. It also alarms on curated lists going stale: every offered band and mode still has a repeater, and no omitted band (4m, 13cm, 6cm, 24GHz, SHF) has gained one.

## WebUSB serial adapters

- **ch340-version-not-bcddevice** (2026-07-28): CH340/CH341 behaviour branches on the chip version from vendor request `0x5F`, not on USB `bcdDevice` (a 0x1a86:0x7523 cable reporting `bcdDevice 0xc233` still reports 0x30/0x31). Version > 0x27 sets bit 7 of the prescaler (otherwise the chip holds data until a full 32-byte packet, stalling short CHIRP replies); version >= 0x30 sets framing through the LCR register pair, older parts stay at their 8N1 defaults.
- **webusb-vendor-filters-are-too-broad-for-wch** (2026-07-28): FTDI and Prolific can be filtered by vendor id alone, but WCH's 0x1a86 also covers CDC-ACM parts (CH9102/CH343) and non-serial chips. The CH340 chooser filters on exact vendor/product pairs so those fall through to the CDC polyfill.
- **loopback-cannot-verify-baud** (2026-08-15): a TX-to-RX jumper proves nothing about baud rate, since both directions use the same divisor. Divisor math is checkable only against published encodings (the unit tests) or a second adapter cross-wired at a known rate. Loopback does cover framing at packet boundaries, byte transparency (0x11/0x13), idle handling, read timeouts and reopen. `web/js/loopback-suite.js` runs against any Web Serial-shaped port: native, the four WebUSB drivers and the CDC polyfill.
- **webusb-chip-ports-have-no-getsignals** (2026-08-15, revised 2026-08-19): the FTDI, PL2303 and CH340 drivers implement `setSignals` but not `getSignals`, so CTS/DSR/DCD are unreadable on them (and on the WebBluetooth port); native Web Serial has both. CP2102 is the exception: `GET_MDMSTS` (0x08) returns the input lines, so it implements `getSignals`. Only the loopback page reads input lines; its control-line case skips ports without `getSignals`.
- **one-bulk-in-transfer-at-a-time-drops-bytes** (2026-08-17): issuing the next `transferIn` only after the previous resolves leaves the endpoint unqueued, and the chip's RX FIFO overruns silently (`status: "ok"` everywhere). Measured on a Pixel 10 (Chrome 151) at 115200 on all three original chips: CH340G (32-byte endpoint) lost bytes on every 16 KB echo; PL2303HX 3/10 runs; FT232R 2/30 runs (64-byte endpoint, 4 ms latency timer, 256-byte buffer: wider margin, same defect). 9600 and 57600 never lost data. Linux (`ch341.c` via `usb_serial_generic_submit_read_urbs()`) keeps two URBs always queued; a JS resubmit crosses Chrome IPC and the event loop, so every driver uses `READ_PIPELINE_DEPTH = 16` plus a matching stream `highWaterMark` (default queue of 1 still dropped a packet at depth 8). At ~7% failure per run a clean run proves nothing; the fix rests on reproduction plus the structural argument. A bare pump benchmark is less sensitive than the suite, whose per-chunk buffering helps starve the endpoint.
- **ch340-strands-exact-multiple-replies-on-multi-packet-reads** (2026-08-17): larger `transferIn` requests are not the cure. A bulk IN transfer ends only on a short packet or the full length, and the CH340 sends no terminator, so against a 512-byte request a reply that is an exact multiple of 32 bytes (the shape of a fixed-size clone block) never arrives. Throughput comes from queue depth; every driver requests exactly one packet. (A PL2303HX does terminate multi-packet transfers, but a non-terminating chip hangs forever, so the rule applies everywhere.)
- **driving-the-loopback-page-on-a-phone** (2026-08-17): chip defects show up on phones, which no CI covers. Rig: wireless adb (`adb pair <host>:<pairingPort> <code>`, then `adb connect <host>:<connectPort>`; ports differ, both from `adb mdns services`, pairing only advertises while the dialog is open). `adb reverse tcp:8000 tcp:8000` serves `npm run dev`; `http://localhost:8000` is a secure context on Android, so WebUSB works without HTTPS. `adb forward tcp:9222 localabstract:chrome_devtools_remote`, then CDP: `Target.createTarget` (Chrome for Android has no `/json/new`), `Runtime.evaluate` with `userGesture: true` for `requestDevice()`, then `import()` the driver and loop `runLoopbackSuite`. One run is ~21 s.
- **cp210x-requests-are-interface-addressed** (2026-08-19): unlike FTDI/PL2303/CH340 (device recipient), CP210x UART requests use `bmRequestType 0x41/0xc1` (interface recipient) with `wIndex` = interface number, and WebUSB requires a claimed interface matching `index`. `VENDOR_SPECIFIC` (0xFF) is device-recipient but still puts the interface number in `wIndex` (`cp210x_read_vendor_block()`). The number comes from the descriptor; hardcoding 0 addresses the wrong port on CP2105/CP2108.
- **cp210x-vendor-wide-filter-needs-a-dispatch-guard** (2026-08-19): the chooser filters Silicon Labs' 0x10c4 vendor-wide because ~150 kernel `id_table` entries are OEM cables with custom product ids, and a device absent from the chooser leaves no diagnostic. But 0x10c4 also covers CP2105/CP2108, HID CP2110/CP2112, SPI CP2130 and the CP2102C, which shares ids but enumerates as CDC-ACM. So `isCp2102Device()` rejects known non-single-UART product ids and anything declaring a CDC interface class (descriptors are readable before `open()`).
- **webusb-bulk-out-failures-do-not-reject** (2026-08-19): `transferOut()` resolves with `{status, bytesWritten}` instead of rejecting, so a bare `await device.transferOut(...)` treats stalled and short writes as success. The CP2102 driver checks status, clears a halted endpoint and resumes short writes. **FTDI, PL2303 and CH340 still use the unchecked form**; fixing them is a separate hardware-verified pass.
- **cp210x-event-mode-is-not-cleared-by-enabling** (2026-08-19): per AN571, event-insertion mode is cleared only by USB reset or `IFC_ENABLE(UART_DISABLE)`; enabling leaves it on, and inherited event mode splices 0xEC escapes and status into data that still looks plausible. The driver disables before enabling.
- **cp210x-flow-block-transforms-bytes-too** (2026-08-19): `ulFlowReplace` bits 2-4 rewrite received data (substitute on parity/framing error, discard every NUL, substitute on break). NUL stripping silently shortens a clone image. They are cleared together with the XON/XOFF and RTS bits.
- **cp2102n-errata-e104-and-e106** (2026-08-19): **E104**: A01 firmware reads the first byte of `ulXonLimit` as `ulFlowReplace`, so a threshold of `0x80` selects RTS flow control; both thresholds are written as zero. **E106**: disabling the UART does not reset DTR/RTS, which could hold a radio in clone mode; `close()` drives both low before `PURGE` and disable.
- **cp210x-holds-flow-control-in-a-block-nothing-resets** (2026-08-19): `IFC_ENABLE` does not reset the `SET_FLOW` block (CTS/DSR/DCD handshaking, DTR/RTS modes, XON/XOFF). Inherited XON/XOFF eats 0x11/0x13; inherited CTS handshaking lets the radio gate our transmit. The driver read-modify-writes the block at every open (constructed fallback if `GET_FLOW` fails).
- **baud-rate-is-latched-at-open** (2026-09-05): Web Serial has no in-place re-rate (`getInfo()` does not even report the rate); only `close()` + `open()`, which needs no user gesture or chooser because permission belongs to the `SerialPort` object. (node-serialport has `port.update({baudRate})`, used by `tests/support/radio-harness.mjs`.) CHIRP drivers declare `BAUD_RATE` from 9600 to 115200, so `prepareClone` re-applies the selected driver's rate before every clone (issue #76). Traps: a reopen swaps the reader, so a read loop must stay pinned to the reader it started with; a failed reopen leaves the port open at no rate and must be torn down.
- **webusb-chip-ports-are-8n1-only** (2026-09-05): all four WebUSB drivers ignore `open()`'s `dataBits`/`stopBits`/`parity` and program 8N1 (grep "dataBits/stopBits/parity" in each); baud rate is honoured. A reopen with `parity: "even"` would succeed and misframe every byte, so these ports (and the WebBluetooth port) declare `supportsFraming = false` and `reconfigure()` refuses a framing change. No flag means the port honours framing (native Web Serial, CDC polyfill). Affects the radios in **framing-is-set-after-open-but-never-mid-clone**. Real framing support is per-chip encoding work (FTDI `SIO_SET_DATA`, PL2303 line coding, CH340 LCR, CP210x `LINE_CTL`) that needs hardware to verify.
- **cp210x-quantises-baud-host-side** (2026-08-19): `SET_BAUDRATE` (0x1E) takes a raw u32 rate, which the chip silently maps to one it can generate; above 1053257 the result is undefined (AN205). The driver ports the kernel's host-side quantiser (AN205 Table 1 for CP2101/2/3, `div = round(48e6 / (2 × prescale × request))` from CP2104 on). All CHIRP rates are exact table entries, so it only clamps.

## Hosting & deployment

- **pages-deploy-and-cache-window** (2026-07-22, host moved 2026-09-19): Pages deploys `dist/` via `.github/workflows/pages.yml`, HTTPS enforced (Web Serial, WebUSB and WebBluetooth need a secure context). The live host is `https://webchirp.org/` (formerly `codeplug.org`, see **the-second-production-domain-is-apex-only**), named in `./CNAME`, which `scripts/retain-deployed-assets.mjs` reads instead of taking a hostname argument (the two once drifted silently for a week). Pages serves a fixed `Cache-Control: max-age=600`, so for up to 10 minutes after a deploy a stale `index.html` can request old hashed asset names. Mitigation: fetch the deployed `asset-manifest.json` and carry the previous generation of hashed assets, and the previous pin's `web/chirp/chirp-<pin>.zip` and manifest, into the new artifact (chained via `retained-assets.json`, 30-day max age). Tabs boot the runtime lazily and can request their pinned archive days after page load, which motivates the 30-day window beyond the Pages cache lifetime. Retention retries downloads and fails the deployment if assets or inventories cannot be read, rather than publishing a partial history; copies use eight workers. Pyodide still loads from jsDelivr.
- **retention-deadlocks-a-cname-only-domain-move** (2026-09-19): retention runs in the build job and throws when the `CNAME` host serves nothing, but Pages only registers a custom domain from a deploy, so editing `CNAME` alone deadlocks. The guard stays strict (a new domain and a typo look identical); the throw's message carries the remedy. Correct order: set the domain out of band (Settings → Pages, or `PUT /repos/:owner/:repo/pages` with `cname`), wait for `https_certificate.state` = `approved`, then land the `CNAME` commit. Any other push to `master` in between redeploys the old `CNAME` and flips the domain back.
- **build-dist-hashes-dependency-first** (2026-09-08, issue #114): `scripts/build-dist.mjs` names each asset after its rewritten bytes, walking the reference graph dependencies-first (Tarjan's SCC), so a dependency-only edit renames its importers too; otherwise a cached importer requests a dependency name that no longer exists and the app goes blank. Members of an import cycle share one digest of the whole group, so a name is not always the digest of its own bytes; that is why retention checks HTTP status instead of re-deriving names.
- **build-dist-rewrites-are-textual** (2026-08-03, widened 2026-08-07, narrowed 2026-09-08): `scripts/build-dist.mjs` finds references by text rather than by parsing, but since 2026-09-08 each match is anchored on path boundaries — neither neighbour may be `[\w./-]`. That retires the trap this entry used to lead with: a comment reading "see web/js/analytics.js" used to ship as "see web/js/analytics.c6e8292118.js", because `/js/analytics.js` matched inside it, and `./analytics.js` likewise matched inside `../analytics.js`. Harmless-looking while it only damaged prose; once the same matching fed a dependency graph it welded unrelated modules into fake import cycles, which is how it was found. Still textual, so a string spelled *exactly* like a reference is rewritten wherever it appears — which is why the convention is that prose names a module by its **canonical repo-root path** (`web/js/ui/format.js`), never dist-relative (`./js/ui/format.js`, indistinguishable from a real import) and never partial (`ui/format.js`, which resolves from nowhere and hides renames). The other half is unchanged and still bites: a file outside `REWRITE_EXTS` (`.html/.js/.css`) is copied verbatim, so `manifest.webmanifest` is never rewritten and anything it points at must be an unhashed path or it will 404 in `dist/` — which is why the icons live in `web/images/`. Until 2026-09-29 `.mjs` was in **neither** set: the shared logic modules shipped unhashed and unrewritten, with no cache-busting on a host where **pages-deploy-and-cache-window** says the headers cannot be set. That stopped being harmless once a hashed `.js` imported a *new* export from one (`runtime-errors.mjs` in PR 205): a new importer served beside the previous deploy's cached module fails to link and blanks the app. `.mjs` is now in both `HASHED_EXTS` and `REWRITE_EXTS`, pinned by `tests/build/build-dist.mjs`.
- **model-pages-are-build-output-not-source** (2026-09-13): `web/radios/` (model pages, vendor hubs, vendor directory), `web/sitemap.xml` and `web/robots.txt` are generated by `scripts/build-model-pages.mjs` (`npm run build:pages`, run by `build:dist` and `dev`) and gitignored on purpose, so catalog or CHIRP bumps do not bury real diffs. All page kinds share one flat directory, since Pages has no redirects; a hub slug colliding with a model slug fails the build. Tracked inputs: `web/radio-catalog.json`, `radio-features.json` (repo root, written by `scripts/build-catalog.mjs`, outside `web/` so browsers never fetch it), `radio-firmware.json` and `radio-specs.json`. Nothing on a page is invented; a thinly described radio gets no page. Tests run the generator against a throwaway tree (`tests/build/model-pages.mjs`).
- **radio-specs-are-researched-not-generated** (2026-09-24): `radio-specs.json` (repo root, keyed `vendor|model`, every catalogued model present; all-null means "looked, found nothing") holds hardware facts no driver knows. Lessons: **driver bands are not radio bands** (Chinese HT drivers accept wide ranges regardless of market version), so the page labels the spec table separately. **"Dual watch" is not dual receive**; only true second-receiver radios (Kenwood TH-D7x/TM-V71, Icom IC-W32/ID-51, Wouxun KG-UV8D/9D, Yaesu FT-8x00) are `true`. **Maker figures are often inflated**, so conflicting sources leave a field null; `min` power is null when only a maximum is published ("Up to N W"). **Bands pair RX with TX per band** (`{band, rxMHz, txMHz}`, 2026-09-25): do not cut a continuous range at conventional edges, and check manuals for receive gaps (US cellular 824–894 MHz, Yaesu 729–800 MHz) that rigpix flattens. `1.25 m` means only 219–225 MHz or a set sold as a 220 rig; 200–260 MHz on unlocked Chinese HTs is `Other`.
- **variant-is-what-separates-drivers-sharing-a-name** (2026-09-16): vendor + model does not identify a driver; 12 model names map to 2–4 driver classes (four are Quansheng UV-K5), told apart only by the catalog's optional `variant`. ## PWA / install

- **pwa-install-needs-no-service-worker** (2026-08-02): Chrome needs no service worker to install an app (since 108 on Android, 112 on desktop). `web/manifest.webmanifest` plus 192 and 512 icons is enough for a WebAPK, so do not add a pass-through worker. A worker would only buy deterministic caching, because a WebAPK uses Chrome's evictable HTTP cache. Doing that is real offline work: Pyodide and `web-serial-polyfill` come from jsDelivr, and it has to fit the hashed-asset scheme in `scripts/retain-deployed-assets.mjs`. Startup reads only `web/radio-catalog.json` and does not boot Pyodide (**static-driver-catalog**).
- **installable-is-not-discoverable** (2026-09-18): meeting Chrome's install criteria gets almost no installs on Android. The ambient badge depends on engagement heuristics and stays suppressed for months after one dismissal. So `web/js/install-prompt.js` cancels `beforeinstallprompt` and keeps the event, and `web/js/ui/install-button.js` raises it from a toolbar button. Platform constraints behind the design:
  - Cancelling removes the browser's own offer, so only `index.html` loads the module. `about.html` keeps the native prompt.
  - The event can fire before the UI binds, so the listener lives in a head module and the UI reads `isInstallAvailable()` at bind time.
  - `prompt()` on a used event rejects, so the event is dropped before prompting.
  - `appinstalled` reaches only the window that installed. Other tabs hear about it over a `BroadcastChannel`, and fall back to window-local behaviour where that is missing or throws.
  - `bindInstallTracking()` (`web/js/analytics.js`) listens without cancelling. One funnel covers both pages: `pwa_install_prompt` → `pwa_install_clicked` → `pwa_install_choice` → `pwa_installed`.
  - Headless Chrome on localhost fires the event, so the button shows up in `web/images/screenshot-narrow.png`.
- **the-rich-install-dialog-is-a-manifest-feature** (2026-09-18): Chrome shows the rich install dialog (description plus screenshot carousel) only when the manifest has `description` and `screenshots` with a `form_factor` that matches the device. Otherwise it silently shows a bare sheet. `narrow` is the Android form factor. `scripts/update-screenshots.mjs` captures the narrow shot with `mobile: true` (needed to get below the 900px and 560px breakpoints) and `scale: 2`, scrolled to `#channel-editor`, because on a phone the sidebar sits above the editor.
- **webapk-start-url-changes-take-days** (2026-08-05): a `start_url` change takes a day or more to reach installed apps. Chrome re-reads the manifest about once a day and then queues a WebAPK re-mint. Until then, hits carry the old `dl`. Check `location.href` in the running app first, and use a fresh install to confirm the manifest.

## Analytics

- **analytics-has-to-be-gated-at-the-tag** (2026-08-07): every copy of the app ships the same measurement ID, and the vendor tag sends `page_view`/`session_start` without being asked. So `web/js/analytics.js` injects the gtag loader itself, only after `location.hostname` passes `ANALYTICS_HOSTS`. Neither page has a static loader tag. As a result, analytics cannot be seen on localhost: check changes in unit tests or on production. `trackEvent` swallows a `gtag` that throws, because content blockers often stub it with one that does.
- **the-second-production-domain-is-apex-only** (2026-09-19, rechecked 2026-10-03): `./CNAME` is `webchirp.org`, and `codeplug.org` 301-redirects to it. `ANALYTICS_HOSTS` and `SENTRY_HOSTS` list `codeplug.org`, `www.codeplug.org` and `webchirp.org`. The `api.codeplug.org` CORS allowlist lives on the server, can't be tested from here, and matches exact origins (scheme included, `Vary: Origin`). It accepts `https://codeplug.org` and `https://webchirp.org` and rejects both `www` names. A `www` host would therefore send telemetry while every repeater query failed.
- **pwa-traffic-needs-a-marker-on-every-hit** (2026-08-03): a WebAPK launch has no `Referer`, so it looks like a direct visit. `start_url` carries `?utm_source=pwa&utm_medium=homescreen`. The manifest's `"id": "/"` keeps a `start_url` change from orphaning existing installs. A `display_mode` parameter goes on every hit. **GA4 ignores custom parameters set with `gtag("set", …)`**, so they must go on the `config` call or on each event. A unit test can pin the call shape but not the payload. To verify for real, inspect the collect URL's `ep.*` params over `chrome://inspect`. GA sends custom params whether or not they are registered, so a missing param was never attached. Headless Chromium ignores emulated `display-mode`.
- **ga-custom-dimensions-are-syncable** (2026-08-04): `npm run ga:dimensions` (`scripts/ga-dimensions.mjs`) compares the GA property with `CUSTOM_DIMENSIONS`, and `-- --apply` creates what is missing. Admin API constraints:
  - `parameterName` and `scope` cannot change.
  - Dimensions can only be archived, not deleted.
  - Registration is never retroactive.
  - `displayName` allows only letters, digits, underscores and spaces. The script checks this locally because creates run one at a time with no rollback.
  - Access comes from GA Property access management (Editor), not Cloud IAM.
  - Turning the measurement ID into a property ID needs account-level visibility, hence `--property`.
- **ga-event-scoped-slots-are-a-one-way-budget** (2026-08-07): 28 EVENT-scoped dimensions are declared, against a limit of 50 (`SCOPE_LIMITS`). Given the constraints above, a slot spent is spent for good. Prefer adding a dimension to an event that already fires over minting a new event.
- **browser-brand-takes-two-sources-and-an-async-probe** (2026-09-08): every Chromium derivative puts `Chrome/` in its user agent. The telemetry brand detector in `web/js/ui/format.js` checks Edge, Opera, Vivaldi, Samsung and plain Chromium (whose UA carries both tokens) before Chrome. It prefers `navigator.userAgentData.brands`, and GREASE entries fall through to no match. Brave can be told apart only with the async `navigator.brave.isBrave()`, which is cached, so until it settles the answer is "chrome". This detector is separate from `detectBrowserVersion()`, which falls back to the whole UA string for issue reports. Browser and OS are not declared to GA because they are built-in dimensions.
- **encoding-declaration-has-1024-bytes** (2026-08-07): `<meta charset>` must sit within the first 1024 bytes, so it is the first line of `<head>` on both pages. A comment block above it once pushed it out, causing mojibake over `file://`.

## Error reporting (Sentry)

- **api-traces-need-streaming-and-their-own-redaction** (2026-10-08): `web/js/sentry-tracing.js` records first-party HTTPS API requests at 100% sampling and propagates `sentry-trace` and `baggage` only to `api.codeplug.org`. SDK 10.73.0 needs both `traceLifecycle: "stream"` and `spanStreamingIntegration()` to record parentless requests after page load. Streamed spans bypass `beforeSend`; `withStreamedSpan` sanitizes the final span attributes, while `createDsc` removes the transaction name before baggage or envelope headers can include a lookup callsign. Page-load/navigation and unrelated request spans are disabled. Deployment requires the API's CORS allowlist to accept both tracing headers; this frontend change does not configure that backend.
- **sentry-needs-the-same-host-gate-as-analytics** (2026-09-06): the DSN is in every copy of the app, so `web/js/sentry.js` checks `SENTRY_HOSTS` and then loads the SDK with a **dynamic** `import()`. A static import or tag would be fetched before the gate runs. A DSN is not a secret.
- **sentry-tracing-is-not-a-call-graph, and profiling cannot work here** (2026-09-06): the two are different products and only one of them was ever plausible on this host. *Tracing* (`tracesSampleRate`) records spans the SDK instruments — page load, resource fetches, XHR/fetch, user-interaction timings — so it answers "what took how long", never "which function called which". *Profiling* (`browserProfilingIntegration`) is the one that yields real sampled call stacks, and it is built on the JS Self-Profiling API, which the browser only exposes when the document is served with a `Document-Policy: js-profiling` **HTTP header**. There is no `<meta>` equivalent for that header, and per **pages-deploy-and-cache-window** GitHub Pages serves a fixed, non-configurable header set — so browser profiling is unavailable here at any effort short of moving off Pages to a host with header control. What does survive is the part that answers the question in practice: the JS **stack trace** on every captured error is the call chain at the moment of failure, and it is readable as-is because `build-dist.mjs` hashes and rewrites filenames but never minifies, so no source maps are needed or uploaded. Python frames are not JS frames — a CHIRP failure's traceback is never a clickable Sentry stack, only redacted prose; since 2026-09-29 it rides in the event's `python` context (attached in `beforeSend` from the `RuntimeCallError`, scrubbed like any other string) rather than in the exception value, which is now the one-line message (see **runtime-errors-cross-as-an-envelope**).
- **a-crash-report-needs-a-signal-not-a-proxy** (2026-09-06): `web/js/runtime-bootstrap.mjs` owns the Pyodide boot. It is a separate module because `web/js/runtime-rpc.js` can't be imported under Node without a hook (**cdn-imports-need-a-resolve-hook-under-node**). Rules:
  - Report a crash on an explicit bootstrap failure, never on "the handle is unset".
  - Publish the handle only after seeding succeeds.
  - Drop a rejected attempt instead of caching it.
  - Dedupe by **error identity**: everything queued behind one attempt rejects with the same object. A boolean latch can't re-arm, because success is cached, so it would hide a later, different failure.
  - Mark errors in a `WeakSet`, not on a property, so the marker never ends up in a Sentry payload.
  - `reportActionError` skips capturing an error that is already marked, so one failure is one event.
- **reportActionError-is-the-one-capture-funnel** (2026-09-06): every action-level failure goes through `reportActionError` (`web/js/ui/debug-log.js`). Cancellations go to `reportActionCancelled`, so dismissing the port chooser files nothing. Tags reuse the analytics `classifyErrorKind`/`errorTypeName` vocabulary. Radio identity comes from a provider registered with `setContextProvider` in `web/js/ui.js`, so it is read at failure time and is also attached to unhandled errors.
- **error-reports-are-where-user-data-leaks** (2026-09-06): CHIRP messages carry user data, such as frequencies and channel names. `beforeSend` redacts frequencies (decimal and Hz), coordinates, locators, quoted values, codeplug file names and URL query strings. Exception **types** and quoted **paths** (traceback `File "…"` lines) are kept on purpose. Console breadcrumbs are dropped entirely. The file-name rule matches a single token on purpose: widening it to catch names with spaces eats the surrounding sentence.
- **the-reportable-failure-happens-before-the-reporter-loads** (2026-09-06): the likeliest failure, the runtime never starting, happens before the CDN SDK is ready. So `initSentry` installs its own `error`/`unhandledrejection` listeners, buffers up to ten captures, replays them once the SDK loads, and then removes the listeners so nothing is reported twice. `version.json` is fetched alongside the SDK, and if it is missing only the release tag is lost.
- **sentry-metrics-are-a-second-pipeline, not a second kind of event** (2026-09-08): `@sentry/browser` 10.x metrics (`Sentry.metrics.*`) ride the trace pipeline and do not need tracing.
  - `enableMetrics` and `enableLogs` both default to true. `enableLogs` is set to false explicitly.
  - **`beforeSend` never runs for metrics.** `beforeSendMetric` does instead, and the SDK has already stamped `user.*` by then. So metric attributes go through an allowlist of keys (`METRIC_ATTRIBUTES`), with scrubbing on top.
  - Scope attributes set with `setAttribute()` are merged in *after* that hook, bypassing the allowlist, and no option prevents it. `web/js/sentry.js` must never call it.
  - Buffered metrics snapshot their context when queued, not when sent.
  - The SDK batches metrics (1000 items or a 5 s idle flush), so one recorded during unload can be lost.
- **two-questions-are-two-group-bys, not two metrics** (2026-09-08): `web/js/ui/metrics.js` records only `flow.completed` (counter) and `flow.duration` (ms distribution), with `flow` and `outcome` as dimensions. Group by `flow` to find broken flows, or filter to one flow and group by `radio` to find failing radios. `blocked` (stopped by preflight validation) is separate from `failed`. A cancelled import is not recorded.
- **metrics-inherit-the-transport-and-nothing-else** (2026-09-08): errors get browser and OS from the default `httpContextIntegration`, but metrics skip event processors. With `sendDefaultPii: false`, server-side UA/IP inference is `"never"`. Anything a metric needs, `browser` and `platform` included, has to be attached explicitly through the context provider in `web/js/ui.js`.
- **a-guard-the-user-can-clear-is-not-a-defect** (2026-09-16): the loudest thing in the Sentry project was `RuntimeUnsupportedError: No cached radio image for this model. Download from radio first, then upload.` — a user pressing Upload on a page where nothing had been downloaded yet, reported once per user who did it, full Python traceback attached. Nothing there is actionable: the message *is* the fix, and the app behaved exactly as designed. The general shape is that `RuntimeUnsupportedError` had been carrying two unrelated meanings — "this driver cannot do that", which is a capability gap worth reading, and "you have not done the previous step", which is not — and no filter could tell them apart, because both arrive as the same class name in the same traceback text. Splitting the second into `RuntimePreconditionError` (`web/python/webchirp_bridge/runtime_errors.py`) makes the distinction visible on the JS side of the boundary, which is the same trick `ImageDetectionError` plays for the all-drivers retry (the class now crosses as a field, per **runtime-errors-cross-as-an-envelope**; until 2026-09-29 it was matched in the traceback text). The drop is one check in `beforeSend` (`isIgnoredError`, `web/js/sentry.js`, reading the hint's `originalException`; a regex in `IGNORE_ERRORS` until 2026-09-29) rather than a return in `reportActionError`, because a precondition failure can also reach the SDK as an unhandled rejection through the global handlers `initSentry` installs — `reportActionError` is the one *capture funnel*, not the one path into Sentry. Matching the class name and not the sentence matters more than it looks: the sentence is user-facing copy, so improving its wording would silently un-ignore the error, and a filter that stopped matching looks identical in the Sentry UI to one that never fired. The other half of the same problem is that dropping the report left the user with nothing: this app has exactly one visible surface for a failure — `setStatus()` writes into the Debug Output panel, per **runtime-errors-cross-as-an-envelope** — and that panel is folded away by default and shows a Python traceback when it opens, which is the right treatment for a defect and the wrong one for an instruction. So the same predicate now routes a precondition failure to a modal (`web/js/ui/notice-modal.js`) carrying only the exception's sentence — once the traceback's **last line**, now the envelope's `message` — rather than the first line `errorSummary()` took while the traceback was the message, "PythonError: Traceback (most recent call last):". The modal is generic on purpose — a title and a sentence, nothing about radios — and `reportActionError` decides which failures earn one, so this stayed a change to the one capture funnel rather than to the upload path. Adding it surfaced a trap in the test harness worth knowing about: the fake DOM vivifies any `#id` as a bare element, so every `.modal-overlay` reads as *open* (`isModalOpen()` is `!classList.contains("hidden")`), and the global Escape handler closes the topmost open surface and stops — so a newly added modal silently swallows Escape in every unrelated test that drives a different one. `closeVivifiedModals()` in `tests/support/fake-dom.mjs` now owns that list.
- **chirp.errors-is-an-api-boundary, not a severity boundary** (2026-09-18): the noisiest survivor after **a-guard-the-user-can-clear-is-not-a-defect** was `chirp.errors.InvalidDataError: No channels found` — a user importing a CSV their spreadsheet exported without a header row — and the obvious fix, ignoring the whole `chirp.errors` module, is wrong in a way worth writing down. Upstream CHIRP is a desktop app where every one of those classes ends in the same dialog box, so the module never had to separate "the user handed us something we cannot use" from "we asked for something that does not exist", and three of its classes are squarely the second kind: `FrozenMemoryError` (1 raise site, `chirp/chirp/chirp_common.py:673`) fires only when code mutates a memory it was told not to; `InvalidMemoryLocation` (36 raise sites) means this app computed a channel bound the driver rejects; and the bare `RadioError` catch-all (1071 raise sites, by far the volume driver) is where a short read from the Web Serial stand-in (`web/python/webchirp_bridge/serial_pipe.py`) would surface — the one failure class upstream has never had to see, because upstream talks to a real serial port. `IGNORED_CHIRP_ERRORS` (`web/js/sentry.js`; a regex in `IGNORE_ERRORS` until 2026-09-29) therefore names eight classes rather than the module. Two properties make that safe and are not visible from either side. The error envelope names the module that *defines* each class (**runtime-errors-cross-as-an-envelope**) and the rule is exact on class and module, so `RuntimeUnsupportedError` and `ImageDetectionError` keep reporting despite subclassing `errors.RadioError` — a class-hierarchy filter over the envelope's `bases` would have swallowed them, an exact one does not. And per **sentry-metrics-are-a-second-pipeline, not a second kind of event**, `ignoreErrors` is an `InboundFilters` event processor that never touches metrics, so the `flow.completed{outcome:failed, error_kind, error_type, radio_module}` counters in `web/js/ui/metrics.js` still answer "what share of imports fail on this driver" for every class dropped here. The live risk is an upstream rename: a filter that stops matching is indistinguishable in the Sentry UI from a failure that stopped happening, which is why `tests/channels/chirp-error-filter.mjs` reads `chirp/chirp/errors.py` and fails if any named class is gone.

## GitHub PR gotchas

- **pr-refs-go-stale** (2026-07-22): a PR's `base.sha` is fixed at creation, and `headRefOid` can stop syncing after pushes. To fix it, retarget the base and back (`gh pr edit N --base <other>`, then `--base master`). `GET /repos/{owner}/{repo}/compare/master...<head>` always shows the true diff. Debug in this order: `git ls-remote`, then the compare API, then the PR's `headRefOid`.
- **actions-can-report-into-a-pr-without-a-third-party** (2026-09-08): limits of GitHub's own PR reporting channels:
  - `::warning file=…,line=…::` annotations render only 10 per level per step.
  - A sticky comment is found by a hidden HTML marker, then PATCHed. Use `gh api -F body=@file` for the body, which is capped at 65,536 characters.
  - Fork PRs get a read-only token, so gate the comment step on `head.repo.full_name == github.repository`.
  - `$GITHUB_STEP_SUMMARY` needs no permissions and works for forks.
- **patch-coverage-must-diff-against-a-ref-not-base-sha** (2026-09-08): `scripts/coverage-patch.mjs` diffs `origin/master...HEAD`, never `pull_request.base.sha` (stale, see **pr-refs-go-stale**). It needs `fetch-depth: 0`, and it filters out changed JS comment lines by hand (**v8-line-coverage-counts-comments-and-blanks**).
- **issue-form-prefill-is-silent-when-wrong** (2026-08-16): an issue-form prefill URL silently drops any param that isn't a field `id` in the template, and an over-long URL gets HTTP 414. - **lookup-perspective** (2026-09-16): `<perspective>` depends on the upstream source: przemienniki.net entries say `repeater`, RepeaterBook ones say `radio`. So the output frequency may be in `qrg type="rx"` or `type="tx"`; match against both.
- **lookup-cors** (2026-09-16): allows `https://codeplug.org` and any `http://localhost:<port>` or `http://127.0.0.1:<port>`. Other origins, including `https://jasiek.github.io`, get HTTP 403 with an empty body, not a missing CORS header.

*Pinned by tests* (`tests/channels/callsign-lookup.mjs`, `tests/channels/ui-repeater-map.mjs`): callsign is case-sensitive (upper-cased in `callsignFromName()`); one callsign can return several sites, picked by frequency in `pickLookupEntry()`; `0.000000/0.000000` means no position; 404 is cached as an answer.

## Cost of previewing a repeater query

- **preview-cost** (2026-09-13): `api.codeplug.org/przemienniki` is one request of about 9 kB (30 km) to 15 kB (100 km), about 210 ms. `api-beta.rsgb.online/locator/<square>` is about 76 kB and 290 ms **per square**, and a radius covers 1-9 squares (`squaresForRadius`, max 24). This is why the preview query is debounced (`PREVIEW_QUERY_DEBOUNCE_MS`, `web/js/ui/repeater-query.js`) and why RSGB caches per square.
- **preview-overfetch** (2026-09-13): proxied directories filter by distance upstream. The preview asks for 1.5x the radius (`PREVIEW_RANGE_FACTOR`, `web/js/ui/repeater-sources.js`) and dims stations outside the ring. The viewport only reaches about 1.11x (`PREVIEW_RANGE_FILL`, `web/js/ui/query-fields.js`), so the caption counts what `renderStaticMap` drew, not what it was given.

## Country licensing guides

The coverage audit is `LICENSING_RESEARCH_SUMMARY.md`. Guide data is in `licensing-*.json` at the repo root.

### Sources and stale facts (2026-09)

- **licensing-input-list**: the analytics country export (81 places plus `(not set)`) is only a list of inputs. `(not set)` cannot get a page.
- **licensing-no-society**: per the IARU directory, Myanmar's BARTS no longer exists. Where no national society website can be verified, say so and link the IARU directory. Never invent one.
- **licensing-cept-vs-tr6101**: CEPT membership and T/R 61-01 visitor operation are separate facts. AU, CA, IL, NZ, PE, ZA and US implement T/R 61-01 without being members. Russia's membership is suspended. A visitor right depends on the licence class and is not a resident licence.
- **licensing-stale-sources**: these older sources must not be used for new applicants:
  - Poland: UKE pages with fees from before 2026-05-01. Current fees: exam 150 zł (75 zł under 18), permit 82 zł.
  - Mexico: IFT is an archive and CRT now handles this. The 2025 law changed the category to a registration certificate. The 2026 CRT lineamientos were a consultation draft only, so there is no verified form, fee or deadline yet.
  - France: forms showing the €46 tax. The tax was removed in 2019 and the exam has been free since 2021.
  - Japan: 4th-class exam fee goes from ¥5,100 to ¥5,700 on 2026-10-01. The guide names both dates.
  - China: the 2012 rule is repealed. The 2024 MIIT rule gives a decision within 30 working days and makes testing and spectrum use free.
  - Vietnam: older RFD regional process. Applications now go through a provincial public service centre, with an 11-day decision.
  - Kazakhstan: the initial third-category licence is a free eLicense notification, with no entry exam.
  - Singapore: the SARTS local exam is suspended. Do not use visitor-licence fees or times for resident applications.
  - Moldova: ANRCETI procedure. The May 2026 ARCOM regulation splits a free exam and certificate from a later frequency licence.
  - Taiwan: NCC pages saying the application window is 1 year. It is 10 years (Art. 9, amended 2020-07-10, law.moj.gov.tw K0060145).
- **licensing-open-conflicts** (2026-10): Romania (ANCOM Decision 245/2017 Art. 18(3)) must issue within 30 days. Ecuador's ARCOTEL page (2025-12-22) says 0.05 + 1.00 SBU, about USD 506, while the older FAQ says USD 5-10. This stays partial until a payment notice confirms it. Belgium's BIPT FAQs disagree between free and EUR 63.30 to file plus EUR 63.30 a year.
